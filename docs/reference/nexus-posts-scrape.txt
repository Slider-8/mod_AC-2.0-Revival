Hi!
this.Math.rand(1, 1000) generates a random number between 1 and 1000, and if that number is equal to or lower than this.Const.Companions.TameChance.Default (the same value that's used for taming, found in scripts/companions/companions_library) it's a success.

If you want to change the chances for the tome to drop (without affecting the taming chances) you can just change that line to whatever you want the chances to be, like 100 permille (10%) in this case:

if (this.Math.rand(1, 1000) <= 100)

This mod applies changes to all of the "pet" scripts (any accessory with a "setEntity" key, to be more precise), giving them new functions and such. You can see all of them in scripts/!mods_preload/mod_AC.nut in the mod_AC_foundation function at the bottom. scripts/companions/companions_library.nut holds all current companion types: gt.Const.Companions.TypeList is an easy list to use for setting companion type, and gt.Const.Companions.Library has the actual details of the different companion types.

To create a new Accessory Companion item you could simply do something like this:

local newCompanion = this.new("scripts/items/accessory/wardog_item");

Apologies for this, but changing the serialization version was a mistake in the first place, so this is to remedy that as well as make the mod more savefile-friendly in general.

***** IMPORTANT *****

Version 1.03 changes the Serialization Version to the silly value of 123 in order to make possible vanilla version changes not matter for this mod. If you already have a savefile that uses this mod and you want to continue playing with it: please remove any installed ac_MOD, download and install ac_MOD_fix, load your savefile, re-save it, quit the game, remove mod_AC_fix and then download and install the regular mod_AC.

Changing the serialization version was a bad idea, in hindsight, since it might break parts of the code (that this mod does not necessarily touch) when and if the developers make changes and increase the version of the base game. I apologize for the inconvenience, but I will revert back to not changing the serialization version at all, soon, and once again (de)serialize savefiles like in the initial release (version 1). This means that savefiles made without this mod installed cannot be loaded, and that savefiles made with this mod installed cannot loaded without it, but it shouldn't possibly break anything if and when the developers make serialization version changes of their own.

I am aware of a way to restructure the entire mod to make it possible to load savefiles made without this mod installed, and to make savefiles made with this mod installed loadable without it. It is something I will most likely take care of once I've finished up on various main plans, because it will require quite some doing, but I might just go ahead and make it priority one.. after I've rested up a bit :)
